# Local development setup

## Prerequisites

- Docker Desktop with **WSL integration turned on** for your distro (Settings → Resources → WSL integration).
- Git and Node aren't needed on the host. Everything runs in Sail (PHP 8.5). Host PHP isn't used.

## First run

```bash
git clone git@github.com:pentacore/friendly-friend.git && cd friendly-friend
cp .env.example .env
# Install Composer deps with a throwaway PHP 8.5 container (Sail isn't installed yet)
docker run --rm -u "$(id -u):$(id -g)" -e COMPOSER_HOME=/tmp/c -v "$PWD:/app" -w /app composer:2 composer install
vendor/bin/sail up -d
vendor/bin/sail artisan key:generate
vendor/bin/sail artisan migrate
vendor/bin/sail npm install
vendor/bin/sail npm run dev
```

Tip: `alias sail='sh $([ -f sail ] && echo sail || echo vendor/bin/sail)'`.

## URLs

| What                | URL                                                                       |
| ------------------- | ------------------------------------------------------------------------- |
| App                 | http://localhost                                                          |
| Vite dev server     | http://localhost:5173                                                     |
| Reverb (WebSockets) | ws://localhost:8080 (browsers; the app itself publishes to `reverb:8080`) |
| Horizon             | http://localhost/horizon                                                  |
| Telescope           | http://localhost/telescope                                                |
| Mailpit             | http://localhost:8025                                                     |

The Sail stack runs `laravel.test`, `horizon`, `reverb`, `pgsql`, `redis` and `mailpit` (see `compose.yaml`). The Discord `bot` service starts only with `COMPOSE_PROFILES=bot` (see [bot.md](bot.md)). After changing queued job code, restart Horizon with `vendor/bin/sail restart horizon`.

## Checks (run before every commit, same as CI)

```bash
vendor/bin/sail artisan typefinder:generate --check --strict
vendor/bin/sail composer test        # Rector dry run, Pint, Larastan at max level, Pest
vendor/bin/sail npm run check        # lint and format (vite-plus)
vendor/bin/sail npm run types:check  # vue-tsc
```

Auto-fix: `vendor/bin/sail composer lint` (Rector and Pint), `vendor/bin/sail npm run check:fix`.

## Generated code

- `resources/js/typefinder/`: TypeScript types from Laravel Typefinder. **Committed.** The Vite plugin regenerates them during `npm run dev`. Otherwise run `vendor/bin/sail artisan typefinder:generate`.
- `resources/js/{actions,routes,wayfinder}/`: Wayfinder routes. Git-ignored, generated by Vite.

## AI agent rules (Laravel Boost)

- **Conventions and design decisions** live in `.ai/rules/*.md`, scoped by path. Start with `general.md`; `index.md` (generated by `boost:index-rules`) maps paths to files. Agents read the matching rules before editing.
- **Process rules** (Sail, checks, commits) live in `.ai/guidelines/workflow.md`. Boost combines them with the package guidelines into `AGENTS.md`, and `CLAUDE.md` imports it.
- Agent skills are in `.claude/skills/` and `.agents/skills/`, including Typefinder's skill. The Boost MCP server is configured in `.mcp.json` and `.codex/config.toml`, and runs through Sail.
- After editing `.ai/` (or adding a package that ships guidelines): `vendor/bin/sail artisan boost:index-rules` (new or renamed rule files) and `vendor/bin/sail artisan boost:update`. Commit the results. Conventions, docs and the ROADMAP change in the same commit as the code.

## Browser tests (light and dark mode)

Pages are rendered in a real browser (Pest browser plugin with Playwright), in light and dark mode. They're not part of `composer test`, so run them separately:

```bash
vendor/bin/sail npm run build            # browser tests always use the built assets
vendor/bin/sail composer test:browser
```

One-time setup inside Sail (the system libraries are lost when the container is rebuilt; see ROADMAP):

```bash
docker compose exec -u root laravel.test npx playwright install-deps chromium
vendor/bin/sail npx playwright install chromium
```

Screenshots are written to `tests/Browser/Screenshots/` (git-ignored) for visual review.

## Dev server and Typefinder

`vite.config.ts` has a small plugin that clears Vue's type cache whenever Typefinder regenerates `resources/js/typefinder/`. Without it, pages whose props changed would silently compile with **no props** until the dev server restarts. After pulling this change, restart `npm run dev` once.
